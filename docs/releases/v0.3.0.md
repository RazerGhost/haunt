Haunt 0.3.0: at home on Linux, with any colour you like and a theme file a wallpaper tool can write. It is still in development: expect rough edges, and expect things to change between versions before 1.0. This is a pre-release; it becomes the latest release once it has had some use.

## New

- **Any colour.** Appearance takes any colour as a hex, with a colour picker, and makes its shades from it.
- **The desktop's look (Linux).** With Appearance's "System", Haunt follows the desktop's light or dark as it changes, offers its accent colour as "System accent" (GNOME 47 and later, KDE), and draws the window buttons where `button-layout` puts them.
- **theme.json.** `~/.config/haunt/theme.json` (`%APPDATA%\haunt` on Windows) sets the mode, the colours, the exact colours of the window's parts, the font and, on Linux, a see-through background. Haunt follows the file as it changes, so matugen, pywal or wallust recolour it along with the rest of the desktop; [docs/theming.md](https://github.com/razerghost/haunt/blob/main/docs/theming.md) has their templates.
- **The system's title bar** (Settings, Appearance; Windows and Linux) in place of Haunt's own buttons.
- **Arch Linux and CachyOS**: a `haunt-bin` package with each release.
- **Your editor and terminal in Settings, General.** A custom editor's command (`nvim +{line} {file}`) that can run in a terminal, for Neovim and Helix; and the terminal Haunt opens. Left empty, Haunt uses `$VISUAL`, `$EDITOR` and `$TERMINAL`. VSCodium and Kate join the editors.

## Better

- **Trusting a folder** is always within reach: the shield in the toolbar offers it in every folder, and pull, push, updating submodules and running tests ask to trust the folder instead of being greyed out.
- Editors and terminals are found where installers put them on Linux and macOS: the login shell's PATH, `~/.local/bin`, JetBrains Toolbox and Flatpak; Arch's `zeditor` and `code-oss` too. More terminals: foot, ghostty, wezterm and `xdg-terminal-exec`.
- In a tiling compositor (Hyprland, Sway, niri, i3) the window shows only Close, unless `button-layout` names others.
- "Open with Haunt" on a folder in a Linux file manager opens it.
- A signed commit that fails because gpg's pinentry needs a terminal says what to set.

## Fixed

- In a folder with no hooks or scripts of its own, there was no way to trust it, so pull and push stayed off.
- From the AppImage, Node, test runners and other programs Haunt starts no longer crash on the AppImage's own libraries.
- On Arch without `which` installed, no editor or terminal was found.
- Right-clicking where Haunt has no menu of its own no longer shows the browser's (Back, Refresh, Print); text fields keep Cut, Copy and Paste.
- Editors and terminals Haunt started no longer stay behind as zombie processes on Linux and macOS.

## Install

| System | File |
|---|---|
| Windows | `Haunt_0.3.0_x64-setup.exe` (or the `.msi`) |
| macOS, Apple silicon | `Haunt_0.3.0_aarch64.dmg` |
| macOS, Intel | `Haunt_0.3.0_x64.dmg` |
| Linux | `.deb` (Debian, Ubuntu), `.rpm` (Fedora), or the `.AppImage` |
| Arch, CachyOS | `haunt-bin-0.3.0-1-x86_64.pkg.tar.zst`: download it, then `sudo pacman -U` it |

Haunt needs git 2.24 or later. For TypeScript and JavaScript it uses Node 22.18 or later, or else Bun or Deno; without any of them it still reads the other languages.

## Known limits

- The installers are not signed yet: Windows SmartScreen and macOS Gatekeeper warn the first time you open Haunt.
- The Linux additions were built and checked in containers, but have seen little use on a real desktop yet: the settings portal, Hyprland, a see-through window, and launching editors and terminals. On some NVIDIA or Wayland setups a blank window can be worked around with `WEBKIT_DISABLE_DMABUF_RENDERER=1`.
- `haunt-bin` is not on the AUR yet (its account registration is closed for now); the package comes with the release instead.
- Haunt looks for updates only when you switch that on in Settings, and then links to the new version; it does not update itself.
