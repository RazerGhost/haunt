Haunt 0.3.7: Haunt keeps up with what happens to your folders outside it. It is still in development: expect rough edges, and expect things to change between versions before 1.0. This is a pre-release; it becomes the latest release once it has had some use.

## New

- **Missing repositories.** A tab or recent repository whose folder is moved, renamed, deleted or on a drive that is not connected stays where it was, marked, instead of disappearing. Click it to see why: **Locate…** points Haunt at where the folder is now, and its tab, pin and colour, trust, bookmarks, what you learned of it and its saved call graph go with it; **Remove** takes it away. Left as it is, it opens again by itself when its folder is back. One missing for 90 days is forgotten; the panel says when.
- **Zoom**, as in a browser: Ctrl + and Ctrl − zoom the window, Ctrl 0 goes back to 100%. The level is kept.
- **A stale index.lock.** When a git that stopped left `.git/index.lock` behind, a write says so and offers **Remove lock**. Haunt removes it only when you ask, and not while another git is working.
- **Repair after a move.** Worktrees whose link to the repository broke are marked, with **Repair links**; a worktree whose folder moved can be located. A submodule whose address changed in `.gitmodules` is marked, with **Sync its address**.

## Better

- **Git done outside Haunt shows sooner.** Coming back to the window picks up what changed. A merge, rebase, cherry-pick, revert or bisect started or finished in a terminal shows its banner at once. Worktrees and submodules added elsewhere appear right away, and `git init` in an open folder is noticed.
- **Worktree tabs** now see new branches, tags, fetches and remote changes made in the main repository.
- **New clones appear at once** in the repository manager's folders while it is open.
- **Trust belongs to the folder.** A different folder that turns up at a trusted path (a new clone, another drive with the same letter) is not trusted until you trust it. Settings, Trust marks those and missing folders, and forgets them in one click.

## Fixed

- Dragging tabs failed while one of them was a missing folder.
- An unplugged drive's tabs, pins and colours were dropped at the next start.
- Long paths in Settings, Trust pushed the list past the dialog.

## Install

| System | File |
|---|---|
| Windows | `Haunt_0.3.7_x64-setup.exe` (or the `.msi`) |
| macOS, Apple silicon | `Haunt_0.3.7_aarch64.dmg` |
| macOS, Intel | `Haunt_0.3.7_x64.dmg` |
| Linux | `.deb` (Debian, Ubuntu), `.rpm` (Fedora), or the `.AppImage` |
| Arch, CachyOS | `haunt-bin-0.3.7-1-x86_64.pkg.tar.zst`: download it, then `sudo pacman -U` it |

Haunt needs git 2.24 or later (Repair links needs 2.29). For TypeScript and JavaScript it uses Node 22.18 or later, or else Bun or Deno; without any of them it still reads the other languages.

## Known limits

The same as 0.3.0: the installers are not signed yet, the Linux additions have seen little use on a real desktop, and `haunt-bin` is not on the AUR yet. See the [0.3.0 notes](https://github.com/razerghost/haunt/releases/tag/v0.3.0). On Windows the folder of the repository on screen cannot be renamed while Haunt watches it; switch to another tab first.

Found a problem? Please [open an issue](https://github.com/razerghost/haunt/issues).
